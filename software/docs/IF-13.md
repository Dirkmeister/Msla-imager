# IF-13: Job file (PC to Pi)

v0.1, 2026-11-14. Owner and only writer: L4. Implemented by `pcbimager/job.py` (writer and the checks the Pi loader will run). Everything a job needs travels in one folder: the frames, and a manifest that says when each frame shows, which face is down and how long the exposure runs.

## 1. Folder

```
<job_id>/
  job.json        manifest (UTF-8 JSON)
  e1_f00.png      exposure 1, frame 0
  e1_f01.png      ...
  e2_f00.png      exposure 2 (second side of a double-sided board)
```

Transfer by USB drive or Wi-Fi (REQ-024): copy the whole folder. The Pi never edits a job folder.

## 2. Frames

- PNG, grayscale, bit depth 1 (IHDR color type 0). Lit = 1 = white = UV passes = material stays (copper on negative dry film, REQ-005).
- Native framebuffer size and orientation: 1440 wide x 2560 tall for the LS055R1SX04 at 47.25 µm. The Pi shows each frame 1:1: no scaling, rotation, filtering or color management anywhere in the chain (REQ-002). Lit maps to full-white RGB, unlit to black.
- Each frame is the complete screen. No layering on the Pi.
- The Pi decodes every frame of an exposure into framebuffer format before it sends EXPOSE, so a frame change costs one buffer copy (REQ-012).

## 3. Coordinate frames (how frames were rendered)

All seen from above the LCD, operator in front.

| Frame | Definition |
|---|---|
| board | KiCad top view, mm, x right, y up (Gerber convention) |
| panel | Origin at the panel center (center of the tooling pins). u along the 6 in side, to the operator's right; v along the 4.5 in side, away from the operator |
| image | 2560 x 1440 px landscape, x right along +u, y down along -v. Panel center at (1280 + dx, 720 + dy) |
| native | Image frame rotated by `native_rot_ccw` (numpy `rot90` sense), then flipped left-right if `native_mirror`. This is what the PNGs hold |

The stamp rule: the face being imaged lies face-down on an LCD that faces up, so the screen shows the mirror of what lands on the face. KiCad's top layer is mirrored about the flip axis; its bottom layer is shown as-is. Copper text always reads mirrored on screen. The mirror is an exact pixel flip about the image centerline (rows j to 1439 - j when `flip_axis` is "long").

## 4. job.json

| Field | Type | Meaning |
|---|---|---|
| `format` | "IF-13" | Required |
| `version` | "0.1" | Major.minor. A new minor version only adds optional fields |
| `job_id` | string | Folder name |
| `created` | ISO 8601 with offset | |
| `generator` | string | e.g. "pcb-imager 0.1.0" |
| `purpose` | object | Test ID and notes (free form) |
| `machine` | object | Geometry the frames were rendered for: `pitch_mm`, `image_w`, `image_h`, `native_rot_ccw`, `native_mirror`, `flip_axis`, `mirrored_side`, panel size, guard |
| `calibration` | object | What was baked into the render: `calibration_id`, `offset_px` [dx, dy], `rotation_mrad`, `nominal_s` |
| `polarity` | string | Informational |
| `frame_format` | object | `type` "png", `bit_depth` 1, `width`, `height`, `lit` 1 |
| `exposures` | array | One per UV-on period, in run order (section 5) |
| `zones` | array, optional | Analysis metadata for wedges, maps and coupons: `id`, `t_s`, `centre_in` (panel, as read on copper), `screen_bbox_px` |
| `placement` | object, optional | Converter jobs: reference bbox (mm), rotation, offset |
| `drills_panel_in` | object, optional | Converter jobs: holes as [u, v, diameter] in inches, panel frame. For S-5 analysis and the 3018 |
| `converter_report` | object, optional | Object counts, render counts, warnings |

Unknown fields are ignored.

## 5. Exposure object

| Field | Values | Meaning |
|---|---|---|
| `id` | string | e.g. "E1", "top-copper" |
| `side` | "top", "bottom", "screen" | Face that lies down on the LCD. "screen" = display-only pattern |
| `kind` | "exposure", "display" | "display": show frame 0, UV stays off |
| `time` | object | `{"mode": "fixed", "end_s": 679}`, `{"mode": "nominal", "scale": 1.0}` (end = calibration `nominal_s` x scale), `{"mode": "operator"}` (time entered at the Pi), `{"mode": "none"}` |
| `frames` | array | `{"t_s", "file", "sha256", "lit_px"}` |
| `prompt` | string | What the UI tells the operator before start, e.g. "Panel top face down on the pins, press plate on, lid closed, then start." |

## 6. Timing

- t = 0 is the UV_ON rising edge as the Pi timestamps it (IF-09).
- Frame 0 is on screen before the Pi sends EXPOSE. `t_s` of frame 0 is 0.
- Frame k shows from `t_s[k]` until `t_s[k+1]`. Times do not decrease.
- `end_s` is when the Pi shows an all-dark frame. Every lit pixel's dose ends there. Fixed-time jobs already carry that blank as their last frame.
- Frame-to-UV sync ≤ 0.1 s (REQ-012). The Pi logs the UV_ON edge, each frame change and the UV off edge with the job.
- Proposed, to settle with L3 against IF-09: the Pi sends EXPOSE(ceil(end_s) + 1) so the Nano's timer is a backstop after the Pi's blank, and the Pi's clock sets every zone's dose. The extra second runs under a black frame (leakage 1/CR, S-4). If S-4 shows real black-frame leakage at 405 nm, switch to EXPOSE(end_s) with whole-second end times.
- Wedges and maps use progressive masking: every zone starts at UV on, so each zone sees a real exposure from a cold start, and zone k goes dark at its time.

## 7. Loader checks (Pi side)

Refuse the job if any of these fail; `pcbimager.job.verify_job` runs the same checks on the PC.
1. `format` is "IF-13" and the major version is known.
2. Every frame file exists, its SHA-256 matches, and its IHDR says width x height = `frame_format`, bit depth 1, color type 0.
3. `machine.image_w`, `image_h`, `pitch_mm`, `native_rot_ccw`, `native_mirror` and `flip_axis` match the Pi's own machine config.
4. Frame times start at 0 and do not decrease; for fixed jobs `end_s` ≥ the last frame time.
5. Warn, don't refuse, when `calibration.calibration_id` differs from the Pi's current calibration: the job was rendered with other offsets.

## 9. Open items

- `native_rot_ccw` and `native_mirror` default to 90 and false until L2 runs T-LCD-5 (tlcd5_screen pattern).
- `flip_axis` defaults to "long" (D-14 option B) until L5 decides D-14.
- EXPOSE backstop (section 6) to agree with L3 when IF-09 is published.
- A double-sided job carries two exposures; the UI prompts the flip between them.
